# Sticker Market 利用シナリオ適合対応 — 実装記録 v1.0

## 原則

本実装は既存UI・既存URL・既存主要フローを正本として維持し、利用シナリオ成立に不足する機能を追加レイヤーとして実装する。
既存データの削除、既存IDの変更、既存Checkoutの置換は行わない。

## 実装構成

- `v2.* / v21.* / v211.js / v212.*`: 既存正本
- `scenario_v1_core.js`: 共通データ、通知、分析、製造状態、再購入、レビュー補完
- `scenario_v1_compat.js`: 既存注文状態との互換処理
- `scenario_v1_market.js`: 用途検索、需要、オーダーメイド、問い合わせ、通報
- `scenario_v1_ops.js`: 注文詳細、退会、権利、AI、報酬、製造、管理者業務
- `scenario_v1_stabilize.js`: キャンセル、違反履歴、バリエーション、製造先割当、クリエイター権限追加等
- `scenario_v1_final.js`: 通知導線、シリーズ一覧、分析イベント、AI提案接続
- `scenario_v1.css`: 追加画面のレスポンシブスタイル

## 共通状態

- 注文は既存注文を正本とし、製造注文を関連データとして保持する。
- 再製造は元注文へ関連付け、売上を二重計上しない。
- 返金は注文とクリエイター報酬を連動して調整する。
- 通知は既存 `notifications` を拡張し、注文、製造、レビュー、新作、需要、サポート、報酬、審査を共通管理する。
- 分析は共通イベント領域で検索、検索結果件数、商品表示、詳細閲覧、お気に入り、カート、購入、レビューを記録する。

## 回帰保全

以下の既存フローは置換しない。

- LP → 検索 → 商品詳細 → カート → Checkout → 注文完了
- オリジナルシール作成
- クリエイターの商品登録・作品管理・注文管理・売上管理
- 管理者の商品審査・承認・差し戻し
- お気に入り、注文履歴、レビュー、マイページ、Legal Footer

GitHub Actionsで単一HTML生成、JavaScript構文検証、既存機能マーカー、scenario-fit機能マーカーを検証する。

## 公開デモ上の制約

現状の公開版はブラウザ内データを正本とするデモであり、以下は実サービス連携ではない。

- DB: localStorageベースの模擬データ
- 決済: 模擬決済
- 製造会社: 模擬製造事業者
- 配送: 模擬追跡情報
- AI: 模擬提案
- 通知: アプリ内模擬通知
- 報酬支払・返金: 状態記録のみで実送金なし

本番化時は既存画面・業務フローを維持し、各アダプターを実DB・決済・製造・配送・AI・通知基盤へ差し替える。
